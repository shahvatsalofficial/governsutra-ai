# Contributing

1. Open an issue describing the governance problem and affected workflow.
2. Keep changes scoped, deterministic and privacy-preserving.
3. Add tests for success, missing evidence, malformed input, injection-like content and unauthorized access.
4. Do not add a dependency without explaining license, maintenance, security and offline implications.
5. Never include real secrets, customer records or confidential model prompts in fixtures.
6. Update documentation and `docs/STATUS.md` with verified implementation status.
7. A maintainer reviews changes; automated checks are not a substitute for human governance decisions.
